# Models

| File | Role |
|---|---|
| `tiny_deterministic.onnx` | The served model: input `input` float32 `[N,3,8,8]`, output `output` float32 `[N,4]` |
| `tiny_deterministic.json` | Provenance: generator, SHA-256, tensor signature, tolerance, ORT version used |
| `tiny_deterministic_fixtures.npz` | Reference inputs and outputs at batch 1, 2 and 4 for the Python checks |
| `tiny_b1_io.bin` | The batch-1 fixture in a flat binary layout for the C++ tests and the load generator |

## Provenance

All four files are generated by `scripts/export_tiny_model.py`. No external model or
dataset is involved. The graph is `Reshape([N,3,8,8] → [N,192])` followed by
`Gemm(W[192,4], b[4])`. `W` and `b` are drawn from NumPy's `default_rng(0)` and scaled by
0.1 and 0.01, and the fixture inputs are drawn from the same generator. The weights are
not trained, so the model makes **no accuracy claim**. It exists to exercise the serving
path, batching and numerical parity. It is distributed under the repository's MIT
license.

`tiny_b1_io.bin` layout (little-endian): the 4-byte magic `BFIO`, then int32 batch, int32
input element count and int32 output element count, followed by the input floats and the
output floats.

Regenerate with `python scripts/export_tiny_model.py`. The script also re-verifies
fixture parity and batched-versus-unbatched equivalence. ONNX Runtime may not produce
byte-identical outputs across versions, so after regenerating, commit the model, JSON
and fixtures together.

Negative-test models that violate the tensor contract are in `tests/fixtures/`, with
their generator.
